## State and operation
Reuses public.app_settings, key gift_card_operations:
- gift_card_sales_enabled: false by default (new public purchases/charges).
- gift_card_redemption_enabled: false by default (new online total/mixed payments, mixed charges and in-store redemption).

Open /staff as active Admin/Manager, “Operaciones Gift Cards”. Each button changes only its selected flag through
set_gift_card_operation(text,boolean), a SECURITY INVOKER RPC with explicit role check, row lock and existing RLS.
Flags are read fresh, server-side, no browser storage or long cache. Missing/invalid/network/HTTP/JSON errors -> 503,
fail closed for new admission. No new environment variable is required.
service_role can also use that RPC. Anon, staff, inactive users and users without profile cannot change flags.
public.gift_card_operation_audit records actor UUID (when provided/authenticated), role, timestamp, old/new values and operation;
clients cannot modify audit. The backend service is identified by role when no human actor exists.
Existing kitchen policies/grants are not replaced. Admin/Manager see settings; no public settings read is added.

## Enforcement / exclusions
- gift-card-purchase gate before createGiftPurchase (no pending purchase/provider order for disabled admission).
- gift-card-charge gate immediately before a NEW charge; approved/paid/existing-charge resolution occurs before it.
- create-culqi-order gates Gift Card payloads before creating a new order/reservation; normal orders unaffected.
- create-culqi-charge gates NEW mixed charges after resolving already-paid Culqi evidence; no gate on normal card/Yape.
- SQL BEFORE INSERT guards protect purchases, reservations, mixed attempts and in-store redemption movements.
  Manual redemption balance UPDATE and guarded movement INSERT share the existing RPC transaction: a blocked INSERT
  rolls back the balance update. No original financial RPC body/signature was replaced.
- Existing purchase ON CONFLICT retry is not a new SQL purchase; its frontend charge still requires admission.
- Online completion of a previously admitted reservation is NOT gated. No flags in culqi-webhook, reconcile, status,
  quote, public digital page, apply/finalize, manual no-charge resolution or audit.
- Manual issuance/creation from /staff remains the existing authorized Phase 1 workflow; sales flag governs PUBLIC sales.
  Manual redemption is suspended for all roles: do not allow Admin to bypass a financial incident switch.

Turning flags off NEVER releases reservations, reverses debits, deletes attempts or cancels provider orders.
Admission before the flag change may complete, including an HTTP already in flight or an external Culqi order already payable.
The switch is not provider-side cancellation and does not abort admitted operations. They continue through audited resolution.
SQL guards lock the settings row FOR SHARE, serialized with flag changes; the setter locks it FOR UPDATE.
